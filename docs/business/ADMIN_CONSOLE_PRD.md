> **历史规划，不是当前后台范围。** 现行后台定位与版本路线以 [PRODUCT_PRD.md](./PRODUCT_PRD.md) 为准。当前是瘦控制台：资源来源、SKU、实例任务、用户、订单、审计；推理管理为可选。线索池已撤出。

> 文档版本：V1.0  
> 日期：2026-08-24  
> 关联文档：[算力供应平台总 PRD](./GPUHOME_PARITY_PRD.md)  
> 使用对象：平台运营、资源运维、财务、销售、客服、风控、内容和管理人员  
> 明确边界：本期没有供应商后台，所有合作方资源由平台内部人员维护或通过内部适配器同步。

## 1. 后台定位

运营管理后台负责把“GPU 资源”转化为“可售 SKU”，并保障从用户下单、自动交付、用量计费到售后处理的完整内部运营流程。

后台不直接承载 Kubernetes、虚拟化或合作方 API 的具体执行逻辑。它通过内部控制面发起任务、查看状态并处理异常，不能绕过任务系统直接修改底层状态。

### 1.1 已确认的业务模式

| 项目 | 方案 |
|---|---|
| 资源来源 | 自有资源 + 少量固定算力供应合作方 |
| 对外产品 | 容器云为主，裸金属询价和拼租意向为辅 |
| 容器云 | 自动下单、调度、交付和计费 |
| 裸金属 | 展示参考配置和价格，销售人工报价与交付 |
| 拼租 | 首期收集意向，运营人工组织与交付 |
| 盈利 | 供应成本与销售价格价差，企业客户单独报价 |
| 供应方权限 | 无供应商账号、无供应商登录入口、无供应商工作台 |

### 1.2 后台设计原则

- 资金、库存、实例状态都以服务端真实数据为准；
- 高风险操作必须二次确认、审批或双人复核；
- 所有写操作都有操作人、请求 ID、前后值摘要和结果；
- 供应成本与用户销售价分离，成本仅对授权角色可见；
- 合作方接口失败不能伪装为平台操作成功；
- 列表、详情和导出遵循同一权限与数据范围；
- 不允许直接修改余额、账单、实例状态或支付结果；
- P0 先保障商业闭环和人工兜底，不追求过早自动化。

## 2. 后台角色与权限

### 2.1 内部角色

| 角色 | 主要职责 |
|---|---|
| 超级管理员 | 系统初始化、角色授权、紧急处置；不参与日常运营 |
| 运营管理员 | SKU、价格、库存展示、活动和平台配置 |
| 资源运维 | 区域、集群、节点、GPU、实例任务和故障处理 |
| 财务 | 充值、账单、对账、退款、发票、成本和毛利 |
| 销售 | 裸金属、拼租、企业方案线索和交付跟进 |
| 客服 | 用户问题、工单、有限度查看实例和订单信息 |
| 风控 | 实名、异常登录、支付风险、反挖矿和黑名单 |
| 内容运营 | 官网内容、公告、帮助文档、客服渠道和协议发布 |
| 审计员 | 只读查看高风险操作、资金和权限变更记录 |

### 2.2 权限域

权限使用“功能权限 + 数据范围 + 敏感字段权限”三层模型。

功能权限：查看、创建、编辑、审批、执行、导出、删除。  
数据范围：全部、指定区域、指定资源来源、本人线索、所属团队。  
敏感字段：供应成本、毛利、手机号明文、实名信息、连接凭据、支付信息。

## 4. 经营看板

### 4.1 页面目标

让管理人员快速判断收入、库存、交付和异常，不在看板直接执行高风险动作。

### 4.2 筛选

- 时间：今日、昨日、近 7 天、近 30 天、自定义；
- 区域；
- 资源来源：自有/合作方/具体内部来源；
- GPU 型号；
- 产品类型；
- 用户类型：专业用户/企业/子账号。

### 4.3 指标卡

- 新增注册、实名、首充用户；
- 充值金额、消费金额、退款金额；
- 供应成本、销售收入、毛利和毛利率；
- 运行实例、关机实例、创建失败；
- GPU 总量、可售、已分配、利用率；
- 缺货 SKU；
- 裸金属线索、拼租意向、待联系线索；
- 严重告警、欠费实例和风控处置。

### 4.4 图表

- 收入、成本、毛利趋势；
- GPU 型号收入与利用率；
- 区域库存和售出率；
- 创建实例漏斗；
- 创建失败原因；
- 充值和支付渠道成功率；
- 企业线索阶段漏斗。

### 4.5 验收

- 指标定义可查看；
- 金额口径和财务账单一致；
- 供应成本只对授权角色显示；
- 图表可下钻到对应列表；
- 刷新不会造成重复查询风暴；
- 数据延迟在页面明确标注。

## 5. 资源来源

### 5.1 页面目标

内部管理自有资源和固定合作方资源。这里的“合作方”只是内部资源来源记录，不产生外部账号或工作台。

### 5.2 来源列表

字段：

- 来源 ID；
- 内部名称；
- 类型：自有、合作方；
- 接入方式：本地 Agent、Kubernetes、API、人工；
- 覆盖区域；
- 结算币种和周期；
- 联系人信息（仅授权角色）；
- API 健康状态；
- 库存同步时间；
- 启用状态；
- 备注。

筛选：类型、接入方式、区域、状态、同步异常。

### 5.3 来源详情

页签：

1. 基础资料；
2. 接入配置；
3. 区域和资源；
4. 成本规则；
5. 同步日志；
6. 结算记录；
7. 操作审计。

接入密钥只保存到密钥管理服务。页面只显示已配置状态、更新时间和轮换入口，不回显明文。

### 5.4 操作

- 新建内部来源；
- 编辑非敏感资料；
- 测试连接；
- 手动同步库存；
- 暂停同步；
- 禁止新调度；
- 恢复调度；
- 归档来源。

规则：

- 禁止新调度不影响现有实例运行；
- 有运行实例的来源不可删除；
- 归档前必须完成实例迁移或确认保留策略；
- 连接测试只返回结果摘要，不暴露密钥；
- 成本变更不追溯已结算账单。

## 6. 区域、集群、节点和 GPU

### 6.1 区域与可用区

字段：区域名称、城市、可用区、资源来源、网络状态、存储状态、是否对外展示、排序、维护状态。

操作：创建、编辑、启停销售、设置维护窗口、配置用户端展示名。

### 6.2 集群与节点列表

字段：

- 集群/节点 ID；
- 来源和区域；
- 主机名和管理 IP（脱敏）；
- CPU、内存、系统盘、数据盘；
- GPU 型号、数量和占用；
- 驱动/CUDA 能力；
- 容器运行数；
- 健康状态；
- 调度状态；
- 最近心跳；
- 温度、功耗、GPU 利用率；
- 告警数量。

状态：正常、亚健康、维护中、禁止调度、离线、故障、退役。

### 6.3 GPU 设备

字段：设备 UUID、节点、型号、显存、MIG/虚拟化能力、健康、占用实例、温度、功耗、错误计数。

操作：隔离设备、解除隔离、健康检查、标记维护、查看使用历史。

### 6.4 高风险操作

- 禁止调度：需要填写原因；
- 强制隔离：影响运行实例时需二次确认和审批；
- 节点下线：必须先展示受影响实例；
- 退役：确认没有运行实例、未完成任务和未迁移数据。

### 6.5 验收

- 心跳超时自动改变健康状态；
- 设备占用与实例配置一致；
- 库存统计不能把隔离或故障 GPU 计入可售；
- 节点操作有任务进度，不以按钮点击作为成功；
- 合作方 API 与平台库存不一致时产生告警。

## 7. 容器云 SKU 与定价

### 7.1 SKU 列表

字段：

- SKU ID；
- 对外名称；
- 来源、区域；
- GPU 型号、显存、数量；
- vCPU、内存；
- 系统盘、默认数据盘、最大扩容；
- 当前可售库存；
- 按量/日/周/月/夜价格；
- 供应成本；
- 预计毛利率；
- 上架状态；
- 标签和排序；
- 最后更新时间。

普通运营看不到供应成本字段。成本和毛利只对财务及授权管理者显示。

### 7.2 新建/编辑 SKU

基础配置：名称、来源、区域、GPU、卡数、vCPU、内存、系统盘、数据盘。  
销售配置：支持计费方式、用户销售价、最低余额、库存阈值、到货提醒。  
展示配置：标签、推荐位、排序、卡片说明。  
交付配置：调度模板、镜像兼容范围、网络和存储策略。

### 7.3 价格版本

每次调价创建价格版本：

- 生效时间；
- 失效时间；
- 供应成本；
- 用户销售价；
- 操作人；
- 调价原因；
- 审批状态。

规则：

- 已生效包周期订单不随新价格变化；
- 按量实例从明确的计费边界切换新价格，并提前通知；
- 销售价不得低于最低允许毛利，除非有审批；
- 调价页面实时显示各计费方式的预计毛利；
- 用户 API 永远不返回供应成本。

### 7.4 上下架

状态：草稿、待审核、已上架、已下架、仅企业可见、已归档。

上架检查：

- 有可用资源或允许显示到货提醒；
- 至少一种价格有效；
- 已绑定可用镜像；
- 用户展示字段完整；
- 供应成本和销售价通过校验；
- 调度模板验证通过。

下架规则：不影响现有实例；禁止新建；保留订单和价格历史。

## 8. 裸金属商品与拼租产品

### 8.1 裸金属商品

字段：型号、GPU 数量/显存、CPU、核心数、内存、系统盘、数据盘、地区、参考月价、库存描述、是否支持测试、交付周期、展示状态。

操作：新建、编辑、上架、下架、复制商品、关联咨询表单。

规则：

- 用户看到的是参考价，不直接生成可支付订单；
- 商品关联内部资源来源，但不对外展示供应方；
- 销售最终报价单独保存，不回写覆盖商品参考价；
- 下架商品保留历史线索关联。

### 8.2 拼租产品

P0 字段：GPU、显存、地区、CPU、单卡参考价、卡位数、资源配置、租期、展示进度、意向人数。

P0 操作：新建展示项目、编辑、开/关收集意向、查看意向、人工标记跟进结果。

P0 明确不包含：平台内预付款、自动占位、自动成团、自动退款。

P1 扩展：真实团、支付、占位、成团阈值、截止时间、退款和交付。

## 9. 实例中心

### 9.1 实例列表

筛选：实例 ID、名称、用户、手机号、子账号、状态、区域、来源、GPU、计费方式、创建时间、欠费、异常任务。

字段：

- 实例 ID/名称；
- 用户和归属子账号；
- 来源、区域、节点；
- SKU、GPU、vCPU、内存；
- 镜像、系统盘、数据盘；
- 状态和最近任务；
- 计费方式、单价、到期；
- 累计消费；
- 创建/开机时间；
- 风险标签。

### 9.2 实例详情

页签：

1. 概览；
2. 生命周期任务；
3. 资源与节点；
4. 网络和开放端口；
5. 磁盘和数据任务；
6. 镜像与重置记录；
7. 订单和账单；
8. 监控；
9. 风控；
10. 审计日志。

连接密码、SSH 私钥等凭据默认不显示。客服只能发起“重置凭据”协助流程，不能查看原始凭据。

### 9.3 内部操作

普通操作：重试任务、刷新状态、查看日志摘要、发送用户通知。  
运维操作：禁止调度、迁移、故障隔离、强制关机。  
高风险操作：强制释放、跳过宽限期、手工迁移数据、风险封停。

禁止操作：

- 直接把数据库状态从失败改成成功；
- 直接修改用户账单以匹配实例状态；
- 无任务记录地移动实例到其他节点；
- 无确认地查看或导出连接凭据。

### 9.4 实例任务

任务类型：创建、开机、关机、无卡启动、配置变更、定时关机、保存镜像、重置、克隆、迁移、复制数据、释放。

字段：任务 ID、实例、类型、幂等键、状态、进度、执行器、重试次数、错误码、错误摘要、开始/结束时间。

状态：等待、执行中、成功、失败、取消中、已取消、等待人工处理。

每次重试生成重试记录，但保持原业务幂等边界。

### 9.5 调度异常队列

聚合：库存不足、节点离线、合作方超时、镜像拉取失败、存储挂载失败、网络分配失败、凭据生成失败。

能力：认领、添加备注、重试、切换资源来源、转人工退款、关闭告警。

切换资源来源必须重新计算供应成本；如果影响用户配置、区域或价格，必须先得到用户确认。

## 10. 用户、子账号与实名认证

### 10.1 用户列表

筛选：用户 ID、手机号、昵称、实名状态、注册来源、邀请人、账户状态、余额区间、累计消费、风险标签。

字段：用户、手机号脱敏、注册时间、实名、余额、运行实例、累计消费、子账号数、最近登录、状态。

### 10.2 用户详情

页签：资料、实例、订单、账单、资金、代金券、子账号、实名、安全事件、客服工单、审计。

敏感字段查看：

- 点击后说明用途；
- 需要对应权限；
- 可要求二次认证；
- 记录查看人、时间和理由；
- 导出使用更严格权限。

### 10.3 用户状态

正常、限制创建、限制充值、限制端口、风险观察、已冻结、待注销、已注销。

冻结必须填写原因、范围、期限和通知方式。解冻产生独立记录。

### 10.4 子账号

后台可查看主从关系、资源归属、权限、余额模式、配额和累计消费。

内部人员默认不能替用户创建子账号或修改密码。客服协助必须通过用户验证和专门流程。

### 10.5 实名认证

字段：认证类型、姓名脱敏、证件类型、状态、供应商流水号、失败原因、提交/完成时间。

操作：查看结果摘要、重新发起、人工复核、风险标记。证件原图仅在法律和业务确有需要时由极少数授权角色查看。

## 11. 交易与财务

### 11.1 订单

类型：实例预付、续费、拼租（P1）、裸金属合同记录、充值、存储、镜像等。

字段：订单号、用户、类型、业务对象、原价、优惠、应付、实付、支付方式、状态、创建/支付时间。

状态：待支付、支付中、已支付、履约中、已完成、已取消、退款中、部分退款、已退款、异常。

### 11.2 充值单和支付回调

充值单展示渠道单号、平台单号、金额、状态、二维码有效期、回调次数、入账流水。

支付回调页面仅展示脱敏摘要、验签结果、幂等结果和处理日志，不展示完整敏感报文。

人工操作：重新查询渠道状态、重放内部处理任务。禁止手工把未确认支付改为已支付。

### 11.3 账单

账单项：GPU 运行、CPU 无卡、数据盘、文件存储、镜像、企业服务等。

字段：账单号、用户/子账号、实例、时间窗、用量、单价版本、金额、成本、毛利、结算状态。

异常类型：缺少用量、重复用量、负数、价格版本缺失、成本缺失、账实不符。

### 11.4 资金流水

任何余额变化都必须由业务事件生成流水：充值、赠送、消费、退款、代金券、配额调整、人工调整。

人工余额调整流程：申请 → 填写原因和凭证 → 财务复核 → 第二人批准 → 系统生成调整流水。不能编辑或删除历史流水。

### 11.5 退款

字段：退款单、原订单/充值单、用户、申请金额、可退金额、手续费、原因、审批人、渠道状态。

流程：客服/用户申请 → 系统计算 → 财务审核 → 风控审核（按阈值）→ 渠道退款 → 余额冲正 → 通知。

### 11.6 发票

字段：申请人、抬头、税号、类型、内容、金额、可开金额、邮箱、状态、文件。

P0 可由客服微信人工处理，但后台必须记录申请、审核、开具和文件。P1 提供用户在线申请。

### 11.7 对账与成本结算

对账对象：支付渠道、内部资金流水、实例用量、合作方成本账单。

合作方没有后台，其结算数据通过内部导入、API 或财务录入：

- 结算周期；
- 资源用量；
- 应付成本；
- 差异；
- 对账状态；
- 付款记录；
- 附件。

状态：待生成、待核对、有差异、已确认、已付款、已关闭。

## 12. 客户线索与销售

### 12.1 统一线索池

来源：裸金属需求、拼租意向、免费测试、解决方案咨询、客服转线索、人工录入。

字段：

- 线索 ID；
- 来源页面和渠道；
- 产品/预选配置；
- 姓名、联系方式、单位；
- 使用场景、模型、卡数、地区、时长；
- 负责人和协作人；
- 阶段；
- 优先级；
- 预计金额；
- 下次跟进时间；
- 最近跟进记录。

### 12.2 线索阶段

新线索 → 待联系 → 已联系 → 需求确认 → 测试/方案 → 报价 → 合同 → 交付 → 成交/流失。

流失必须填写原因。重新激活保留原历史。

### 12.3 去重与分配

- 按手机号/微信、单位和短期重复提交识别；
- 重复线索合并前人工确认；
- 可按产品、区域、客户类型轮询分配；
- 超过首次响应 SLA 自动提醒主管；
- 销售只能查看自己或团队线索。

### 12.4 跟进记录

类型：电话、微信、会议、测试、报价、合同、交付、备注。

每条记录包含时间、参与人、结论、下一步和附件。不得删除已生效报价和合同记录。

### 12.5 免费测试

流程：申请 → 资质审核 → 资源确认 → 测试订单 → 创建测试实例 → 到期提醒 → 自动停机 → 转正式/关闭。

测试必须设置额度、到期时间和允许操作范围，禁止无限期测试。

## 13. 营销中心

### 13.1 代金券

创建字段：名称、面额、门槛、适用 SKU/产品、有效期、总量、单用户限制、发放渠道。

操作：批量发放、指定用户发放、暂停、作废未使用券、查看使用订单。

已使用代金券不能删除或修改。

### 13.2 邀请

查看邀请人、被邀请人、注册、实名、审核和奖励状态。P0 支持人工审核发放，P1 可规则化自动审核。

### 13.3 充值赠送

配置充值档位、赠送金额、活动时间、用户范围和预算。发放结果生成独立赠送余额流水。

### 13.4 活动

限时价格、热门标签、包夜活动和新人活动必须有开始/结束时间、预算或库存、叠加规则和回滚方案。

## 14. 客服、通知和到货订阅

### 14.1 工单

字段：工单号、用户、实例/订单、分类、优先级、负责人、SLA、状态、用户回复、内部备注。

内部备注永不对用户展示。客服访问用户业务信息遵循最小权限。

### 14.2 到货订阅

展示用户、SKU、通知渠道、订阅时间、通知次数、最后通知、转化订单。

库存到货后支持批次通知和频控。通知不自动锁库存。

### 14.3 通知记录

字段：场景、用户、渠道、模板版本、状态、发送时间、送达时间、失败原因、重试次数。

验证码内容不在后台明文展示。

## 15. 内容中心

### 15.1 官网配置

可配置首页 Hero、推荐 SKU、产品卡、热门镜像、解决方案、CTA、页脚和客服入口。

发布流程：草稿 → 预览 → 审核 → 定时发布/立即发布 → 回滚。

### 15.2 公告和弹窗

字段：标题、内容、目标用户、页面、频次、开始/结束时间、关闭规则、优先级。

紧急维护公告可由运维发起，但仍需记录发布和撤回。

### 15.3 帮助文档

支持栏目、文章、版本、搜索关键词、发布状态和关联产品。文档更新不应要求重新部署前端。

### 15.4 协议

服务协议、隐私政策、反挖矿协议保存版本、摘要、生效时间和是否要求用户重新同意。

协议发布需要法务/管理审批，历史版本不可删除。

## 16. 风控与合规

### 16.1 风险事件

来源：登录、验证码、支付、退款、实例进程、GPU 利用率、端口、流量、邀请和客服举报。

字段：事件 ID、用户、实例、规则、风险等级、证据摘要、自动动作、负责人、状态、处置结论。

### 16.2 反挖矿

能力：

- 进程和行为规则；
- 异常 GPU 满载与网络特征；
- 镜像和脚本风险扫描；
- 自动限制公网、关机或隔离；
- 人工复核和申诉；
- 误报恢复。

自动强制关机需通知用户并保存证据摘要。后台不得向普通客服暴露过多检测细节，避免规则被绕过。

### 16.3 风险处置

动作：观察、限制验证码、限制创建、限制充值、关闭端口、关机、冻结账号、加入黑名单。

每个动作设置范围、原因、有效期、审批要求和恢复方式。

## 17. 系统管理与审计

### 17.1 内部账号

- 禁止共享账号；
- 强制 MFA；
- 支持 SSO（后续）；
- 记录登录设备、IP 和失败事件；
- 离职账号即时禁用；
- 长期未使用权限自动提醒回收。

### 17.2 审计日志

字段：时间、操作者、角色、IP、动作、对象、请求 ID、前后值摘要、审批单、结果。

重点审计：

- 权限和内部账号；
- 供应成本和调价；
- 节点隔离和实例强制操作；
- 用户敏感信息查看；
- 余额、退款、发票和对账；
- 风控处置；
- 协议发布。

审计日志不可由业务管理员修改或删除。

### 17.3 外部服务配置

短信、微信登录、支付、实名、邮件、对象存储、监控和合作方 API。

配置页面只维护密钥引用、启用状态、回调地址、健康检查和更新时间。密钥由专用密钥系统保存。

### 17.4 系统参数

包括：

- 按量计费粒度；
- 关机数据保留天数；
- 余额预警阈值；
- 包夜时段；
- 文件存储和镜像免费额度；
- 到货通知频率；
- 退款和调价审批阈值。

参数变更必须版本化、生效时间明确并支持回滚。

## 18. 关键内部流程

### 18.1 自有资源上架

```text
注册节点
-> 健康检查
-> 识别 GPU/CPU/内存/磁盘
-> 加入区域与资源池
-> 创建 SKU
-> 配置成本与销售价
-> 验证调度模板
-> 审核上架
```

### 18.2 合作方资源上架

```text
内部创建资源来源
-> 配置 API/人工同步方式
-> 测试连接
-> 映射区域和 GPU 型号
-> 配置供应成本
-> 创建销售 SKU
-> 小规模真实交付测试
-> 审核上架
```

整个流程由平台内部人员完成，合作方没有登录步骤。

### 18.3 容器实例自动交付

```text
用户确认创建
-> 订单/余额校验
-> 预占库存
-> 创建调度任务
-> 底层交付
-> 网络和存储挂载
-> 凭据生成
-> 实例运行
-> 开始计费
-> 通知用户
```

任何环节失败都进入异常队列，并按幂等规则释放库存、退款或人工处理。

### 18.4 裸金属和拼租人工交付

```text
用户提交意向
-> 线索去重与分配
-> 销售确认需求
-> 资源运维确认可用性
-> 销售报价
-> 合同/收款
-> 人工创建交付任务
-> 交付并记录凭证
-> 售后跟进
```

### 18.5 调价

```text
提交新供应成本/销售价
-> 系统计算毛利影响
-> 运营/财务审批
-> 生成价格版本
-> 定时生效
-> 用户端缓存刷新
-> 监控转化与毛利
```

### 18.6 退款

```text
发起申请
-> 系统计算可退金额
-> 财务审核
-> 风控复核（达到阈值时）
-> 渠道退款
-> 余额冲正
-> 生成流水
-> 通知用户
```

## 19. 后台交互规范

- 列表默认支持保存筛选和自定义列；
- 敏感字段默认脱敏；
- 批量操作显示影响数量和对象摘要；
- 高风险操作使用明确动词，不使用模糊“确定”；
- 长任务提交后进入任务中心；
- 失败提示包含错误码、影响、可重试性和建议动作；
- 导出为异步任务并通知完成；
- 页面不自动覆盖其他管理员刚刚修改的数据，使用版本校验；
- 金额统一存储最小货币单位，展示明确币种；
- 时间同时保留 UTC 和业务时区，页面默认中国标准时间。

## 20. 非功能要求

### 20.1 安全

- 管理后台独立域名和网络访问策略；
- 强制 HTTPS、MFA、短会话和设备管理；
- RBAC 和数据范围在服务端强制；
- 防止水平/垂直越权；
- 财务和密钥操作二次认证；
- 所有导出加水印和操作人标识；
- 不在日志记录密码、验证码、私钥、身份证明文和支付密钥。

### 20.2 性能

- 普通列表 P95 ≤ 800ms；
- 经营看板 P95 ≤ 2s；
- 大导出使用异步任务；
- 实时指标允许明确的数据延迟；
- 不允许后台大查询影响用户端交易和实例控制。

### 20.3 可用性

- 后台故障不影响运行实例；
- 内容发布失败可回滚；
- 调价和系统参数使用版本化配置；
- 任务操作可恢复、可重试；
- 紧急情况下提供只读降级模式。

## 22. 验收标准

### 22.1 权限

- [ ] 每个角色只能看到允许的菜单和字段；
- [ ] 直接调用无权 API 被拒绝；
- [ ] 成本、实名、手机号、凭据和导出权限分别验证；
- [ ] 临时权限到期自动失效；
- [ ] 权限变更有完整审计。

### 22.2 资源与商品

- [ ] 自有资源和合作方资源可由内部人员维护；
- [ ] 合作方没有任何登录入口；
- [ ] 故障、隔离、维护 GPU 不计入可售；
- [ ] SKU 上架检查完整；
- [ ] 价格版本按预定时间生效；
- [ ] 用户端接口不泄露供应成本和资源来源敏感信息。

### 22.3 实例

- [ ] 实例状态与底层真实状态一致；
- [ ] 每个生命周期操作生成任务；
- [ ] 任务失败进入异常队列；
- [ ] 重试不重复创建实例或扣费；
- [ ] 高风险操作二次确认并审计。

### 22.4 财务

- [ ] 支付重复回调只入账一次；
- [ ] 账单、流水和余额可互相核对；
- [ ] 供应成本、销售收入和毛利口径一致；
- [ ] 人工余额调整需要双人复核；
- [ ] 退款与原订单、渠道和流水关联完整；
- [ ] 历史资金流水不可编辑和删除。

### 22.5 线索与内容

- [ ] 裸金属和拼租提交进入统一线索池；
- [ ] 重复线索有提示，不自动错误合并；
- [ ] 线索分配和跟进记录可追溯；
- [ ] 官网内容可预览、发布和回滚；
- [ ] 协议历史版本保留。

## 24. 产品结论

本期后台是平台内部的统一运营中枢，不是多边撮合市场。固定合作方只作为“资源来源”和“成本结算对象”存在，由内部人员或 API 适配器维护。这样可以显著降低首期复杂度，把研发重点集中在容器云自动交付、可靠计费、库存准确性和人工兜底能力上。

只要后台能够准确回答四个问题，平台就具备运营基础：

1. 当前到底有多少可售 GPU？
2. 每台实例现在真实运行在哪里、状态怎样？
3. 用户消费了多少、平台成本多少、毛利多少？
4. 失败订单、异常实例和客户线索由谁在什么时间处理？
