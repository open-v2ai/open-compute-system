# Auto Router 设计与 MVP

Auto Router 是模型 API 的虚拟模型入口。客户端固定请求 `opencompute/auto`，平台在同一次
Chat Completions 请求内先用小模型判断任务复杂度，再把原始消息交给简单或复杂模型执行。

## 请求链路

```text
API Key / 幂等 / 限流 / 余额预检
                |
                v
      小模型判断 simple / complex
                |
       +--------+---------+
       |                  |
       v                  v
  简单任务模型        复杂任务模型
       |                  |
       +--------+---------+
                |
       Token 结算 / UsageEvent
```

判断器只接收最近一个用户问题、消息数量和请求的最大输出 Token，最多读取 6000 个字符，最多
生成 8 Token，并被独立的短超时约束。系统提示要求它只返回 `simple` 或 `complex`。当前标准：

- 简单：事实问答、改写、翻译、短摘要、直接提取和低约束对话；
- 复杂：多步推理、非平凡代码、数学、长上下文综合或需要同时满足多项约束的任务。

## 配置与发布

运营后台为 Auto 模型配置：判断模型、简单模型、复杂模型、判断超时和判断失败保底档位。
配置存数据库并即时生效。三个内部模型必须已上架、不是另一个 Auto Router，且拥有健康副本；
简单和复杂模型必须不同。Auto 模型未完成配置时不能上架。

判断模型建议使用本地部署的 0.5B～3B 指令模型；演示数据暂用 Mock Qwen3 8B 表示这个位置，
不代表已经完成真实小模型或 GPU 验收。

## 计费与兼容性

- OpenAI 响应的 `model` 始终是客户端请求的 `opencompute/auto`；
- 用户按 Auto 模型自己的固定输入/输出价结算，避免内部切换造成账单不可预测；
- `ocs_router` 返回本次命中的模型、档位和判断来源；
- `UsageEvent` 记录请求模型、实际模型、档位、判断来源、判断模型和判断耗时；
- 判断器 Token 属于平台内部开销，当前不计入用户返回的 Token 用量。

Auto 的成本价应由运营方按实际简单/复杂请求分布与判断器开销设置为保守的混合成本。MVP 尚未
自动计算分类器成本、分模型毛利或动态调价。

## 降级规则

1. 判断器超时、失败或输出无效：走后台配置的保底档位，默认复杂模型；
2. 被选档位没有健康副本：尝试另一个档位，并记录 `availability_fallback`；
3. 两个执行档位都不可用：返回 `503 AUTO_ROUTER_TARGETS_UNAVAILABLE`；
4. 请求 ID 重放：直接返回原 UsageEvent，不重新判断、执行或扣费。

## 后续演进

先用线上 UsageEvent 构造人工标注集，评估正确率、质量、延迟和单次毛利，再考虑置信度阈值、
更多任务档位、规则与模型混合判断、按 Key 的质量/成本偏好，以及分类器 A/B 测试。MVP 不把
未经测量的“智能路由”宣传为质量或成本已经最优。
